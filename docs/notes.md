# Notes module

## Overview

The Notes tab lets a user write Markdown notes, tag them, search them, and see
a live HTML preview. Notes are stored locally in SQLite and are available to
the agent through native tool calling.

## Entity

`entity.Note` is immutable:

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | `String` | UUID generated by the create use case. |
| `title` | `String` | Required, trimmed, nonblank. |
| `markdown` | `String` | Markdown source; may be empty. |
| `tags` | `List<String>` | Normalized tags, case-insensitive deduplication. |
| `createdAt` | `Instant` | UTC creation time. |
| `updatedAt` | `Instant` | UTC last-update time. |

## Use cases

| Package | Input | Success output |
| --- | --- | --- |
| `create_note` | title, markdown, tags | `Note` |
| `list_notes` | query, tag | notes ordered newest-first + all tags |
| `get_note` | id | `Note` |
| `update_note` | id + optional title/markdown/tags (null = keep) | updated `Note` |
| `delete_note` | id | deleted id |

Each use case has its own input/output boundary and interactor, following the
same shape as the Todo module. Validation messages are user-facing, for
example `Enter a note title.` and `Note not found.`

## Persistence

`SqliteNoteDAO` implements `NoteDataAccessInterface` using the shared
`SqliteDatabase` helper. Notes and tags are written in one transaction; tags
use a `note_tag` table with `ON DELETE CASCADE`. The database path, schema and
reset steps are in `database/README.md`.

## Interface adapters and view

- `NotesController` parses comma-separated tags and calls the input boundaries.
- `NotesPresenter` implements the create/list/update/delete output boundaries.
- `NotesViewModel` holds notes, tags and the error message and fires
  `NOTES_LOADED`, `NOTE_SAVED`, `NOTE_DELETED` and `ERROR` property changes.
- `view.NotesPanel` provides the note list, search/tag filters, title/tags
  fields, Markdown source editor and a non-editable `JEditorPane` preview.
  Rendering uses `org.commonmark:commonmark` with raw HTML escaped. The
  preview is debounced by a 300 ms Swing timer.
- Agent-triggered writes refresh the list; dirty editor content is not
  overwritten silently. If the selected note is deleted externally, its text
  is kept as an unsaved draft.

## In-Notes agent pane

`view.NotesAgentPanel` is a compact right-side assistant scoped to the open
note. It offers:

- Quick actions: Summarize, Rewrite, Generate tags, Continue, Explain.
- Free-form input and model/effort selectors.
- A transcript of the conversation.

The panel only sends when a saved note is open and there are no unsaved
edits. It shares the `AgentToolDispatcher` and local memory store with the
Agent tab; its requests use the same notes tools.

### Selection quoting

Select text in the Markdown source or rendered preview and click
**Quote to agent**. `NotesPanel` adds the selection to `NotesAgentPanel`'s
pending context and transcript; the next prompt includes a quoted block, so
the agent can explain or rewrite the exact passage. Quotes are capped at 8,000
characters and cleared when the note changes.

### Edit indication and diff view

- While a Notes-pane agent request runs, a pulsing blue banner with an
  indeterminate progress bar appears above the editor and the panel reports
  "Thinking...". The same banner lights up while any notes write tool runs,
  including calls made from the Agent tab.
- When a write tool updates the open note, `NoteDiff` computes a line-based
  unified diff. The preview area gains a **Changes** tab with GitHub-style
  prefixes and colors (`+` green, `-` red) plus a `@@` hunk header; the tab is
  selected automatically. Click **Preview** to turn the diff view off and
  **Changes** to turn it back on.
- The Changes tab summary shows added/deleted line counts and title/tag
  changes. The summary flashes briefly (a smooth color fade) when a new diff
  arrives.
- The diff is cleared when another note is selected, a draft is started, the
  note is deleted, or the user saves their own edits.
- Conflicting dirty edits are preserved: the diff shows the agent's saved
  change while the editor keeps the user's unsaved text.

## Agent integration

`interface_adapter.notes` exposes five tools through `AgentToolDispatcher`:

- `list_notes`, `read_note`, `create_note`, `update_note`, `delete_note`.

Read/list tools only capture their result. Write tools also notify the shared
`NotesPresenter`, so the Notes tab refreshes. The full contract is in
`docs/agent-tools.md`.
